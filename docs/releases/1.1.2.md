# Veronica 1.1.2

This release addresses six reproduced reliability failures and the gap between artifact promotion and catalog commit. It adds explicit recovery and diagnostics while reducing the instructions loaded when the skill is selected.

## Reliability fixes

1. Malformed `next`, URL and limitation fields are rejected before state/event commit.
2. Usage grouping accepts valid string identities; malformed legacy records remain preserved and make the report incomplete.
3. A failed artifact restore no longer leaves a partial destination. A destination created concurrently is preserved.
4. Projection publication acquires the ledger writer lock before reading its revision. Revision/hash markers expose interrupted generations.
5. Task selection and acceptance traversal handle long dependency chains without recursive stack growth.
6. Concurrent duplicate usage submissions return an idempotent result; conflicting payloads remain rejected.

Capture receipts are persisted before blob promotion. Explicit reconciliation can restore catalog provenance from a valid receipt and intact blob without duplicating the origin. Older orphan blobs with unknown provenance are reported and preserved.

## New optional operations

- `veronica.py doctor --deep`: validate logical state, references, dependency cycles, artifact consistency and projection generation.
- `preserve.py reconcile [--repair]`: inspect artifacts, or explicitly replay valid pending capture receipts.
- `recovery.py bundle / verify / restore`: package the ledger, artifacts and selected product files, verify integrity and resume in a new workspace with old leases expired.
- `context --task ID --index-limit N --index-offset N`: page the unrelated task index explicitly, while keeping selected task details, dependencies and all global notes/effects complete.

These are available when needed; they are not mandatory before every task. Runtime dependencies remain Python 3.10+ and its standard library.

## Compatibility and boundaries

Existing schema-1 ledgers and explicit attempt limits are preserved. The artifact store adds a `capture_receipts` table when opened for writing; existing blobs, origins and usage rows remain intact. Invalid legacy data is reported, not silently rewritten. Standard checkpoints still preserve the process ledger only.

Single-file recovery uses atomic hard-link promotion and was tested on local NTFS. Unsupported filesystems fail rather than use an unsafe overwrite fallback. Bundle/restore destinations must be new and coordinated with other writers. Product writers must be stable for a meaningful snapshot. Credentials, applications and external effects are not recreated; uncertain effects remain uncertain.

The helpers validate mechanical properties. They do not certify semantic quality, long-term stability, exactly-once external actions or general token savings. See [validation evidence](../VALIDATION-1.1.2.md).
